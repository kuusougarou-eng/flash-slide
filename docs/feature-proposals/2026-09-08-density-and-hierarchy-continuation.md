## 確立された設計原則

1. **幾何に依存する表現選択はエンジン(測ってから決める)、意味構造はLLM(1回の推論で決める)。** OOXML直接操作を避ける判断(前の議論)と同じ理由: LLMは最終的な文字サイズ・列幅・折り返し位置を生成時点で知り得ない。
2. **静的な機械的分割より、LLMに複数表現を出させて描画側が選ぶ方が安全。** 「、」区切りでの自動箇条書き化のような静的分割は不自然さのリスクがある。
3. **文字サイズは重要度の階層。余白や密度の問題はサイズでなく整列・表現形式で解決する。**
4. **情報は文字数を理由に削らない。密度が高すぎるときはページを増やす(sections)。ただし入力自体が最初からページ構成を意識している場合(コンサル提案書の13枚構成など)は別の話** — これは次の一手で扱う。

## 追記: 箇条書きの間隔をスライド全体の規則にした(2026-09-09)

原因は間隔が**部品ごと**に決まっていたこと:
- `renderNestedItems` の `extraGap` が、その枠の余りの 55% を項目間に配り、1 か所あたり最大 20pt まで広げていた。
- 単独パネルは「余りが枠の 1/4 超」で等高の格子に切り替わり、行が枠いっぱいに散っていた。

文字サイズと同じ扱いに変えた。間隔はスライド全体で 1 つ(`LIST_GAP`)。`renderBodyPass` が文字サイズを決めた後、
版面がまだ余っている(fill < 0.7)ときだけ 3pt → 6pt と広げ、溢れたら手前の段に戻す。部品側からは触らない。
等高の格子は、左右で行を揃える必要がある兄弟パネルのときだけ残した(`8a261ff` の意図を壊さない)。
格子セルの見出しと 1 項目目の間も、見出しの箱に下マージンまで数えていたぶん(最大 8pt)を外して詰めた。

## 追記: 段落 API の実測と、箇条書きの既定を 1 シェイプに戻した判断(2026-09-09)

### 実測(`hint:"probepara"`, PowerPoint デスクトップ)
`ParagraphFormat._scalarPropertyNames` = **`horizontalAlignment` / `indentLevel` の 2 つだけ**。
`BulletFormat` は `visible` / `style` / `type`、`TextFrame` は 4 マージン + `verticalAlignment` / `wordWrap` / `autoSizeSetting`。
**`spaceBefore` / `spaceAfter` / `lineSpacing` / `leftIndent` / `hangingIndent` は存在しない。**
代入しても例外は出ず `load()` も通る(追跡対象でないプロパティは JS の代入として残るだけ)ので、
`_scalarPropertyNames` を見ないと「効いた」と誤認する。

### そこから決めたこと
- 1 シェイプの中で項目間に余白を作る手段は空段落しかない。それはまさに「箇条書きの間に改行を入れた」見え方。
- ぶら下げインデントが無い問題は**シェイプを分けても解決しない**(点は段落の属性なので、1 項目を独立した箱にしても
  その項目が折り返せば 2 行目は点の下に戻る)。分割で得られるのは実質 4 つだけ:
  ①項目間の余白(裁量)②兄弟パネルの行揃え ③ラベル列の整列 ④セル内で見出しに点を付けない。
  ②〜④は API の穴を埋める構造上の必然、①だけが裁量。
- ①は**やめる**。余白を足せるのは分けた箇条書きだけなので、1 シェイプで描く箇条書きと同じスライドに並ぶと
  必ず食い違う(前日入れた `LIST_GAP` は、ばらつきの原因を部品単位からレンダラ単位に移しただけだった)。

### 実装
- `renderNestedItems` は、②〜④のいずれにも当たらなければ **1 シェイプ・複数段落**で描いて返す。
- 分けたときも項目間の余白は 0 にし、1 シェイプの字送りに合わせる。
- 兄弟パネルの格子の行高は「版面 ÷ 段数」ではなく「自然な字送りを行数単位に丸めた値」を上限にし、
  縮めた分は上下に均等に返す(両パネルで同じ値になるので行は揃ったまま)。収まり判定は `- 4` から `+ 0.5` に緩めた
  (行高が自然高さそのものなので `- 4` では必ず外れ、揃わない流し込みに落ちていた)。
- `LIST_GAP` とスライド一括の行間拡大パスは削除。疎な版面は文字サイズ(既存の版面充填)で埋める。

### 実機で確認したこと
同じ内容の 4 項目の列挙が **4 シェイプ → 1 シェイプ**になり、1 シェイプの列挙・兄弟パネル・ラベル 2 列の
3 種類が同じ字送りで並ぶことを PowerPoint の実描画で確認した。

### 残る論点
疎なスライドは、間隔で埋めなくなったぶん**中央に文字が固まって余白が目立つ**。埋める手段は文字サイズだけで、
本文の上限は 20pt(「24pt は疎なスライドで幼く見える」という以前の判断)。上限を上げるか、疎なときは版面の幅を
狭めて 1 行あたりの字数を減らすか、いずれ判断が要る。**未着手**。


## 追記: 箇条書きの構造を編集容易性から作り直した(2026-09-09)

ユーザー指摘「1 行ずつ箇条書きを分けるのは編集可能性をかなり悪化させる。人間は生成後にそのシェイプを選んで
Enter で新しいビュレットを出して書いたり消したりする。シェイプ単位でやるのは管理の拷問だ」。

### 実機で確かめた Office.js の段落 API(`hint:"probepara"` / `hint:"probeindent"`)
対照(A)を置いて左揃えを明示したうえで比較した。**中央揃えのままでは字下げの判定ができない**(前回これで誤読した)。

| | 手段 | 結果 |
|---|---|---|
| A | 何もしない(対照) | — |
| B | シェイプ全体に `indentLevel = 1` | A と同一。**効かない** |
| C | `getSubstring` で一部の段落に `indentLevel = 1` | A と同一。**段落単位に効かない** |
| D | タブ文字 `\t` | 文字だけ右へ寄り、**点が左端に置き去り** |
| **E** | **ソフト改行 `"\v"`(Shift+Enter 相当)** | **段落が変わらないので子に点が付かず、ぶら下げ位置に揃う** |
| F | `"\r"` | 普通の段落区切り。子にも点が付く |
| **G** | **折り返し** | **2 行目は点の位置に戻らず 1 行目の文字位置に揃う** |

`ParagraphFormat._scalarPropertyNames` は `horizontalAlignment` と `indentLevel` の 2 つだけ。
段落間隔・行間・ぶら下げインデントのプロパティは存在しない(代入しても例外が出ないので `_scalarPropertyNames` を見ないと誤認する)。

### 直したこと
- **箇条書きは 1 行ずつシェイプに分けない**。パネルごとに 1 シェイプ・複数段落。兄弟パネルの行揃えも捨て、
  余った高さは縦中央に置く。ラベル/値の 2 列だけが例外として残っている(下記)。
- **入れ子はソフト改行で親の段落に入れる**。第 1 階層はネイティブの点、子は点なしで一段深く字下げ。
- **子の記号「–」は、子が折り返すときだけ付ける**。1 行に収まるなら字下げだけで階層が読める(記号があると騒がしい)。
  折り返すと記号なしでは子と子の切れ目が消えるので付ける。`nestedText` が幅と文字サイズを測って選ぶ。
- **塊の間に空のソフト改行を 1 本入れる**。点の付かない空行なので、段落間隔の API が無くても区切りが作れる。
  ただし**入り切らないときは捨てる**(8 領域の密なスライドで、空行のぶん溢れて最後の領域が消えた)。
- **`fitBody` の「1 項目 1 行に収める」縮小を削除**。G の結果で前提(折り返すと点の位置に戻る)が誤りと分かった。
  この縮小は「縮んだ」警告を出して版面充填まで止めており、4 項目のスライドが 14pt のままになっていた。
- **版面充填の入口の閾値を 0.70 → 0.85**。塊の空行のぶん充填率が上がって拡大が止まっていた。
  溢れるかは拡大のループが実際に描いて確かめている。

### 確立した原則(追加)
- **編集容易性 > 見た目の作り込み**。生成物はユーザーが PowerPoint で直す前提で、1 シェイプ・複数段落が既定。
  シェイプを分けるのは API の穴を埋めるためだけで、余白や整列のためには分けない。
- **視認性が最優先**。ただし区切り(空行・記号)より内容が入ることが先。
- **検証は必ず対照を置き、`horizontalAlignment = "Left"` を明示してから見る。**

### 残件
- **ラベル/値の 2 列だけ 1 行 2 シェイプのまま**(先日の ① の機能)。点は付かないので箇条書きではないが、
  編集容易性の観点は同じ。落とす(1 シェイプでインライン)/ 残す / PowerPoint のネイティブ表にする、の 3 択で**ユーザーの判断待ち**。
- 疎なスライドの余白の埋め方(本文の上限 20pt を上げるか、版面の幅を狭めるか)。**未着手**。
