# 品質基準(2026-09-10)

「雑然とした文書や ChatAI との対話結果(Markdown の構成案)から、モノトーンのコンサル資料を高速に書き出す」
というプロダクトの価値に対して、何をもって合格とするかを定める。**推論は 1 回**で、収まり・強調・単位・
分割はエンジンが決定論的に決める。判定は `npm test`(`test/quality.test.js`)で機械的に行い、
最終的な見え方は実機の PowerPoint で目視する。

## 3 つの改善レバー

| レバー | 場所 | 何を決めるか |
|---|---|---|
| ① systemPrompt / 出力指示 | `server/prompt.js` | 意味構造(主役の名指し・行の並び・階層・単位の書き方)。表示側の都合を LLM に押し付けない |
| ② JSON の自由度 | `normalizeGeneratedSpec` / `refineComposition` | LLM に許す形(panelCount / body の型 / headFill 等)と、許さない形(自由な入れ子・座標・色) |
| ③ 整形ロジック | `layout.js` → `render.js`(Office.js) | 幾何に依存する判断(折り返し・分割・強調の予算・単位の移動・揃え)を測ってから決める |

## 採点の観点と合格基準

### 視認性(読めるか)
- 本文 14pt 以上、格子のセル 12pt 以上。注記・脚注は 9pt 以上
- 版面の外に出ない。内容が落ちない(`content dropped` / `overflow` の警告ゼロ)
- 箇条書きはパネルごとに 1 シェイプ(生成後に Enter で項目を足し引きできる)。1 行を 2 シェイプに割らない
- 入れ子は親の段落の中(ソフト改行)。子は一段深く字下げし、折り返す子にだけ「–」を付ける
- 薄い地は `#EAEAEA`。濃い地は主役 1 か所だけ

### レイアウト(整っているか)
- 版面充填率 0.30〜0.99(200 字未満の入力は 0.22 以上)。表は版面を埋めてよい
- 格子は版面の下端まで使う。ただし 1 行あたり自然高さの 2.5 倍・+110pt まで(散らさない)
- 縦の揃えは行単位。行に 2 行以上のセルがあれば行見出しも含めて上揃え
- 余りは上 35% / 下 65% に配る(ど真ん中にも上詰めにもしない)
- 矢羽の先端は自分の列(行)の中。列見出しの文字は一番狭い列で 1 行に収まる大きさ
- 単位はセルに散らさず列見出しへ。数値列は多数決(7 割)で右揃え
- 分割は 1〜2 枚が既定、読める大きさで入らないときだけ 4 枚まで。2 枚目の番号は続きから

### 伝達力(伝わるか)
- title は 24 字以内(指示は 10〜18 字)。lead は版面で 2 行以内
- title か lead で主役を名指しし、**結論に名前が出ている行が立っている**(強調ゼロを許さない)
- 入力の数値・固有名詞の **75% 以上**が spec に残っている(1 回の推論で事実を削らない)
- 入力に出典があれば footnote に残る

| 雑然メモ | memo-messy | 285 |

fixture は `node scripts/capture-specs.js` で本物の LLM から 1 回の推論で取る(分割前の応答を保存し、分割はゲート側で試す)。
プロンプトやエンジンを変えたら取り直し、中身を見てから commit する。

## 実行

```bash
npm test                          # 6 スイート。quality.test.js が上の基準を機械判定する
node scripts/capture-specs.js     # fixture の取り直し(サーバ起動が必要)
```

実機の目視は `DEV_TRIGGER=1` でサーバを起動し、`hint:"renderspec"` で spec を描かせて
`scripts/ppt-export-by-id.ps1` で PNG に書き出す(CLAUDE.md の手順)。

## 現在の到達点(2026-09-10、`feature/robust-input-scale`)

- 14 ケースすべてゲート通過。1 回の推論のまま 51 字 → 1 枚、1,330 字 → 4 枚。
- 実機で目視したもの: 雑然メモ(2 枚)、ChatAI 構成案(2 パネル + 出典)、定例報告(5 工程を 1 枚)、
  6 工程の矢羽を 2 枚に割って番号が 01〜03 / 04〜06 と続くこと。
- 直近の採点で直したもの: 主役の行だけ濃く(全行を濃くして強調が消えていた)、単位を列見出しへ、
  「論点: ・」の前置きを列見出しへ昇格(再正規化で戻らないよう収束させた)、
  数値列の右揃えを多数決に、3 行の格子が fill で 2+1 に割れる誤判定、続き番号の欠落。

## 既知の残り

- 定例報告で LLM が矢羽(headShape:"chevron")を選ぶことがある。進行ではなく状態の列挙なので長方形が正しい。
  プロンプトの「進行方向を強く示す必要があるときだけ」をさらに絞るか、エンジン側で「行見出しが工程名でなければ長方形」に落とす。
- 1 行だけの続きページ(3 行を 2+1 に割ったとき)は版面が薄い。3 行が 12pt で入らないケース自体を減らす
  (セル内の行送りを 1.25 に詰める等)方が筋がよい。
- 短い入力(50 字級)は 26pt でも版面が余る。素材が無いときの見せ方(大きな言い切り + 1 図)は未決。
