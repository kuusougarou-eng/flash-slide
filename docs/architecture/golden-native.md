# GoldenPPTXを再現する静的コンパイラ

## 正本と到達条件

2026-09-08のユーザー指示により、正本は `docs/golden/golden.pptx` の32枚。
`docs/golden/README.md` と `scripts/make-golden.py` が構成・設計意図の根拠。
旧 `docs/golden/catalog.json` は旧版の構造なので、32枚の再現評価の正解には使わない。
同様に先行する `test/golden/cases.json` の疎な16例は、今回の品質目標ではない。

**完成条件は正本のコピーができることではない。** 入力が変わっても、高密度な構成・意味関係・数値と図の対応を保ち、単回の高速LLM推論と決定論的な処理で生成すること。

必要な要件は次のとおり。

1. 正本32枚の図形、文字階層、箇条書き、結合表、グラフ、マスタを保持する。
2. 入力の文章・数値・条件を構造化し、元の架空企業のデータを残さない。
3. グラフキャッシュと編集用Excelを同じデータから生成する。
4. 円の面積、棒の長さ、ガント期間、ハーベイボール、RAG、注釈の接続をデータに従って更新する。
5. 行・列・工程・系列の増減と文章量に対して、整列・密度を保って再配置する。
6. 高速LLMは座標やOffice.jsコードを出力しない。意味の構造とデータを一回で出力する。
7. 複数枚と現在のアプリの挿入・差し替え経路を通し、実機で検証する。
8. 未使用の入力で情報保持・意味の対応・実描画・全体時間を測る。

## 実装した描画バックエンド

`server/golden-native/package.js` はPPTXをOOXMLの部品グラフとして読み、選んだスライドと必要な関連部品の閉包を一枚のパッケージへコンパイルする。
原本は書き換えない。無関係なスライド、チャート、埋め込みExcelを除き、レイアウト・マスタ・テーマ・参照画像を保持する。
テンプレート構造はキャッシュする。コピーの静的再現は高速だが、この時間をLLM生成全体の時間とは呼ばない。

`public/render.js` の `insertCompiled` は `insertSlidesFromBase64` と `KeepSourceFormatting` で挿入する。32枚の原本を画像として貼らず、編集可能なネイティブ図形・グラフ・表を保持する。
挿入前後のIDを同じOffice.js操作内で読み、3回の同期で確認する。現時点では `rendernative` 開発トリガだけから検証している。通常の生成経路にはまだ接続していない。

`server/golden-native/charts.js` はカテゴリ・系列・値から、ネイティブチャートのキャッシュ・参照式・編集用XLSXを同時に生成する。系列は1〜8、カテゴリは1〜48。手動の軸範囲を保持したまま値だけ変える事故を避け、自動軸または明示した有効範囲にする。

文章の差し替えは全段落スロットの明示的な指定が必須。未知キー・欠落・推定容量超過をエラーにし、黙って切り捨てない。段落のインデント・余白を保持し、部分太字を指定できる。元のノート本文は消去する。

**差し替えは実験用。** `experimental:true` を必須とし、通常生成から呼ばない。原本の注釈線や図形で描いた数値図は、文字を変えるだけでは正しい位置・大きさにならないためである。

## 追加進捗：量と形状の結合

`geometry.js` に、値から面積円・符号付き棒・期間帯・反復行・座標点を計算する純関数を追加した。スライド番号や企業名を含まない共通の計算である。
`bindings.json` は正本の図形IDと意味上の役割を対応させるオフラインの校正情報。原本ハッシュが変わった場合は、古い図形IDへ誤って書き込まずエラーにする。

`bind-geometry.js` は現在、#30の面積円と#31の順位棒を接続済み。値を変えると図形の大きさと数値ラベルを更新し、順位棒の目標線・目標値も同時に更新する。ゼロの円は非表示とし、小さな円の値が白地に消えないようにする。
元と同じ値で生成した `bound-30.pptx` / `bound-31.pptx` は、PowerPointで元画像と全ピクセル一致。画像は `debug/golden-native/bound-30` / `bound-31` にある。

検証は `node test/golden-geometry.test.js` と `node test/golden-binding.test.js`。
純関数では面積比、ゼロ、大小の逆転、符号付き棒、範囲外値、期間の両端を含む計算、3〜16行の割付を確認した。
OOXMLへの結合では値ラベル・図形サイズ・目標線の位置を検査した。

期間帯と反復行の計算は純関数までで、ガントの図形・期間見出し・担当・節目への結合はまだ未完了。
文章の意味の変化に応じた並べ替え、注釈・状態色・行数の動的更新、単回LLMとアプリ通常経路への接続も引き続き未完了。


## 静的コンパイラ v2: 生成器の移植(2026-09-08 夜)

図形 ID のバインディング(`bindings.json`)は 1 型ごとの手作業校正が要り、32 型に伸びない。
そこで正本の生成器 `scripts/make-golden.py` そのものを JS に移植し、**データ → OOXML** を直接組む方式に切り替えた。

- `server/golden-native/author/xml.js`: python-pptx と同じ形の DrawingML を吐く部品(テキスト・図形・接続線・ネイティブ表・グラフ枠)。
  EMU は Python の round-half-even、接続線は端点を先に丸めてから差を取る、表の枠高は行高の丸め合計、pie の既定段落など、正本と同一になる癖まで再現。
- `layouts*.js`: 32 型の関数。座標は版面(`rows_fill`/`cols_fill`)から計算し、件数・文字量が変わっても再配置される。件数の許容範囲は各関数で検査する。
- `samples*.js`: 正本 32 枚のデータ。移植のオラクルであり、LLM に見せる「型の例」でもある。
- `charts.js` を拡張: 軸の max/min/majorUnit の保持、ウォーターフォールの強調点(dPt)、系列ごとの点ラベル位置の再割当。
- `fit.js`: 幅重み付き文字数から折返し行数を見積もり、入らない箱だけ段階的に縮める(正本データでは無効)。

### 単回 LLM 推論への接続

`author/generate.js`: system プロンプト = 型の選び方 + 書き方 + 32 型のカタログ(型名と、文字列を 24 字・配列を 2 件に省略した例)。約 12k トークン(ゲートウェイ側でキャッシュされ、2 回目以降は 11.5k がキャッシュ命中)。
応答は `{"layout":"NN","data":{…}}` の 1 回。`sanitize` で LLM が決めてはいけない幾何(注釈の指示線、位置不明の today、列幅)を落とし、`compile` で組む。

経路: `POST /api/generate-native {prompt, model, layout?}` → タスクペインの「仕上げの希望 → エンジン: ゴールデン(32 型・ネイティブ)」→ `insertCompiled`。
開発トリガは `engine:"native"`。サーバ起動時にコンパイラをウォームアップする(初回 0.4 秒の解析を生成時に払わない)。

未使用の入力 6 件(`test/golden-author/inputs.json`: 工程計画・委託先比較・リスク・推移・意思決定・KPI 報告)での実測(gpt-5.4-mini):

| 入力 | 選ばれた型 | 推論 | コンパイル |
|---|---|---|---|
| 工程計画 | 13 ロードマップ | 6.8s | 427ms(初回) |
| 委託先比較 | 06 選択肢の比較 | 2.9s | 27ms |
| リスク | 27 リスク表 | 3.0s | 21ms |
| EC 比率の推移 | 03 推移+意味合い | 3.0s | 72ms |
| 意思決定 | 26 意思決定ページ | 3.6s | 26ms |
| KPI 報告 | 17 KPI ダッシュボード | 7.4s | 391ms(初回) |

型の選択は 6/6 妥当。入力の数値・固有名詞はすべて保持され、入力にない数値は出なかった(`debug/golden-native/llm/*.json`)。
実描画は `debug/golden-native/llm-rendered/*.png`。ペイン経由(リスク表)は推論 3.7s + コンパイル 0.4s(初回)+ 挿入 1.2s = 5.4s、挿入後の実描画 `pane-n03-risks.png`。

この過程で直したもの: 状態語(順調/遅延/要注意)を RAG 色に正規化、ハーベイボール未使用時は凡例を出さない、LLM の軸範囲が読めない(目盛 8 本超・余白なし)ときは自動軸に置き換える、`today` のラベルが無ければ今日線を描かない。

### 残り

- 縮小は見積りに基づく。実描画で溢れる箱を検出して縮める検証器(幾何チェッカー)は未着手。
