# パネル数と主図を先に決める生成方式

2026-09-06 のユーザーフィードバックに基づく。別テンプレートの取り込みは今回の対象外。

## なぜプロンプトとエンジンの両方を変えるか

以前は LLM が `fill` / `highlight` と任意の `rows` / `cols` を出力し、エンジンは強調の個数と文字の収まりだけを調整していた。プロンプト内にも「強調しない」という規則と黒い箱・強調付きフローの例が混在していた。

そのため原因と打ち手の対比が「左の格子＋右上の箱＋右下の箇条書き」になり、ステップ図の下にも示唆帯が付いた。強調の個数制限では意味の妥当性を保証できない。

新しい生成では最初の推論で `panelCount: 1 | 2 | 3` を決める。LLM は意味関係・文章・主図の種類を選び、コードは許可された組み合わせと実寸を決める。

| 判断 | 担当 |
|---|---|
| 原因／打ち手などの対立、論点の分割、パネルのサブタイトル | LLM |
| 文章、マトリクス、順序、ガント、数値図、体制図の選択 | LLM |
| 1〜3 パネル、等幅、同じ高さの黒下線 | エンジン |
| 複数パネルの本文はテキストだけ | エンジン |
| 1 パネルの主図は単独、補足は全幅の無地テキスト一つ | エンジン |
| 任意の highlight / fill / 太字指定を除去 | エンジン |
| ステップの番号、文字量と実幅から横／縦を選択 | エンジン |
| 対応する軸が 2 以下ならマトリクスの見出し帯を省略 | エンジン（見出しの意味はセル本文に保持） |
| 8 行以上または 36 セル以上は PowerPoint Table | エンジン |
| フォントの拡大、本文の縦中央配置、図内の行と列の整列 | エンジン |

構造上必要な背景（全ステップの見出し、マトリクスの軸名、期間帯）は同じ役割の要素に統一して付ける。特定の選択肢・右側・先頭だけを塗らない。大小や色ではなく、推奨内容は文章で述べる。

## 実装経路

- `server/prompt.js`: 新しい形式と例。自由な入れ子と装飾指定を出力語彙から除いた。
- `server.js`: 実 LLM の全生成応答を `normalizeGeneratedSpec` に通す。
- `public/layout.js`: `normalizeGeneratedSpec` と `renderComposition` が構造の制約を担う。新規応答には `compositionVersion: 1` が付く。
- 旧保存 JSON と旧モックは既存の正規化・レンダラを残す。新規生成に旧経路を使わない。新形式の JSON 再描画は新経路に戻り、正規化を繰り返しても構造を変えない。
- 複雑な旧ブロックがパネル内に来た場合はラベル・値を含む文章へ変換する。独立した図が複数ある場合や、対応できない数の行・列は黙って捨てずエラーにする。
- 想定外の `body.note` に書かれた切替条件も、無地の補足として保持する。

既存の密度超過時の追加推論は残っている。パネル決定のための追加推論は導入していない。

## 見た目の調整

テキスト主体の本文は 18pt を起点に、全体の収まりを確認して 24pt まで拡大する。パネル見出しは本文より大きく、左右同じ位置に下線を引く。本文は残りの領域の縦中央に置く。短い横ステップは見出しと本文の自然な高さをまとめて配置し、両者を離さない。

ガントのタスク補足は期間帯の右端ではなく、図内の固定列に置く。最終月の補足・マイルストーンも版面内に収める。年度／月の列見出しの span は期間数を超えない。

## 検証と残る範囲

`npm test` で旧形式のレイアウト、参照解析、LLM 接続に加え、新しい構造の制約・情報保持・再正規化・文字配置・ガント端部を検証する。`node scripts/verify-panel-grammar.js` は設定済みの実 LLM で検証用 JSON を `debug/panel-grammar` に保存する。PowerPoint の実描画でも確認する。

この変更は構成と配置の修正。LLM の事実の省略や算術の誤りを一般に保証するものではない。例えばベンダー比較の生成では合計費用の誤計算も確認されたため、その例は完成資料として扱わない。

scatter / bubble / area、レイヤーと説明を対応させる pyramid、写真・名前・役職を見出し上に持つ CV は今回新設していない。追加時も「一つの主図」または CV の専用構造として実装し、自由な入れ子で代用しない。既存の体制図は木構造の位置とコネクタ計算を継続利用する。
