# ゴールデンスライド(品質の正解)

エンジンの制約を外し、python-pptx でユーザーのマスタ上に**直接**組んだスライド。
これが品質の正解であり、高速エンジン(`public/layout.js`)はこれを再現することを目標にする。

- 生成: `python scripts/make-golden.py`(既定マスタ: `~/Documents/プロジェクトアプローチ.pptx`)→ `docs/golden/golden-v1.pptx`
- 書き出し: `powershell.exe -File scripts/ppt-export-file.ps1 docs/golden/golden-v1.pptx debug/golden-v1 1920`(PowerPoint 自身の描画)
- `*.pptx` はマスタ(社内テンプレート)を含むため **git に入れない**(`.gitignore`)。スクリプトだけを管理する。

題材は架空の中堅部品製造 X 社(売上 480 億円)の収益改善。数値はすべて評価用の架空データで、12 枚が一つの物語(現状 → 要因 → 論点 → 選択肢 → 優先順位 → 計画 → 体制 → 進捗)になっている。

## 設計原則(v1 で適用したもの。レビューで更新する)

### 版面と文字
- タイトルは**メッセージ**(結論 + 数値)で 2 行まで。Georgia(マスタ)20〜22pt。プレースホルダを `32,30,896,58` に広げて 2 行を許す。
- リードは 1〜2 行の補足で、タイトルの根拠か「何をどう整理したか」。Arial 13pt、`32,92,896,32`。
- 本文域は `y 128〜492`。出典は `y 494` に 8pt 灰。
- 本文は Arial 9.5〜12pt。格子・表は 9.5〜10.5、箇条書きは 10〜11、見出し帯は 11 太字。KPI の大数字は 26。
- 箇条書きは本物のぶら下げインデント(`buChar` + `marL/indent`)。「•  」の文字列で代用しない。

### 色
- 灰階調が基本。強調色はマスタの橙 1 色を、**列見出しの帯・推奨列・クリティカルパス・折れ線の主系列**にだけ使う。
- 濃灰(#404040)は根・合計・総合評価行など「最上位」だけ。黒塗りを量産しない。
- 薄灰(#F2F2F2)は「読み取り単位」を囲む地(セル、タイル、要点帯)。

### 格子・表
- 行見出しは薄灰の箱、列見出しは帯。左上の角は空ける。
- 罫は行の下に薄灰 1 本だけ。縦罫は引かない。ネイティブ表もセル罫を全部消して同じ見た目にする。
- 数値列は右揃え、文字列は左、見出し帯は中央(1 列だけの見出しは左)。
- 区切り行(第 1 波…)は結合セル + 薄灰。

### 図
- 折れ線・積み上げ・棒は**ネイティブグラフ**(値ラベル付き、凡例は下、目盛線は薄灰)。主系列だけ橙、他は中灰。
- ウォーターフォールは積み上げ棒の透明ベース。始点・終点は濃灰、減少は橙、増加は中灰。値ラベルは棒の上に手描き。
- ハーベイボールは円 + 扇形(PIE の adj で角度)。
- ガントの帯はホームベース型(五角形)。今日線は破線 + 濃灰の小ラベル。
- ツリーはコネクタ線を「親の右 → 縦の幹 → 子の左」で引く。

### 密度
- 1 枚に**主図 + 補助(小表または要点帯)**を必ず置く。余白が 60pt 以上残るなら小表を足す。
- 主図の右列は「意味合い/読み取り/判断」の見出し帯 + 太字の小見出し + 箇条書きで、最後に So what。

## 次にやること
1. ユーザーのレビュー → 原則の更新 → v2。
2. 正解が固まったら、`layout.js` を「この正解を再現する」方向に作り替え、`docs/golden` との一致率で品質を測る。
